# Tauri 2 shell reference

## Files

| File | Role |
|---|---|
| `src-tauri/tauri.conf.json` | name, version, identifier, window, bundle metadata (publisher Synopus), updater endpoint + public key |
| `src-tauri/Cargo.toml` | crates: `tauri`, `tauri-plugin-{opener,process,updater,single-instance,window-state}` all `"2"` (latest 2.x on `cargo update`) |
| `src-tauri/src/main.rs` | plugin registration (single-instance first), native menu, About panel with credit + website |
| `src-tauri/capabilities/default.json` | permissions for local pages only: core, opener, updater, process restart, window-state |
| `www/` | generated by `sync_web.py` (boot + offline, or web build + offline) |

`withGlobalTauri: true` exposes `window.__TAURI__` (including `updater`, `process`, `opener`) to the local boot page so it can run the update flow without a bundler.

## Updater flow

1. CI builds with `createUpdaterArtifacts: true` and the signing key → installers + `.sig` files + `latest.json` (`version`, `notes`, `pub_date`, `platforms.<target>.{url,signature}`).
2. The release is a draft. Publishing it makes `releases/latest/download/latest.json` resolve.
3. On launch the boot page calls `updater.check()` (4 s cap). If a newer version exists it offers "Install and restart" or "Later"; download progress shows in the bar; `process.relaunch()` restarts.
4. Tauri validates the whole `latest.json` before reading `version`: every platform entry must be complete. A partially failed CI matrix must not be published.

Windows install mode: `bundle.windows.nsis.installMode: "currentUser"` installs without admin rights, which keeps updates silent. Change to `perMachine` only if IT policy needs it.

## Platform build prerequisites

- **Linux**: `libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf` (Ubuntu 22.04+). Build on the oldest Ubuntu you support (glibc compatibility).
- **macOS**: Xcode command line tools. Build both `aarch64-apple-darwin` and `x86_64-apple-darwin` (CI matrix does).
- **Windows**: WebView2 is preinstalled on Windows 10/11; the NSIS installer bootstraps it when missing.

## Windows signing options

- **Azure Trusted Signing** (cloud, no hardware token): configure `bundle.windows.signCommand` per Tauri's Windows signing guide and add the Azure credentials as secrets.
- **OV/EV certificate (.pfx)**: `bundle.windows.certificateThumbprint`, `digestAlgorithm: "sha256"`, `timestampUrl`; import the cert in CI before `tauri-action`.
Check Tauri's current "Windows Code Signing" guide before setting either up; the options change.

## Upgrading

- Patch/minor (2.x): `npm i -D @tauri-apps/cli@latest`, `cargo update`, `cargo check`.
- A future major (3.x): read the migration guide, run `npx tauri migrate` when offered, then re-run parity and a full CI build before releasing. Note the `createUpdaterArtifacts: "v1Compatible"` setting is only for apps migrating from Tauri 1.

## Live-mode hardening (optional, for sensitive apps)

Restrict navigation to the live host by handling `on_navigation` in a `WebviewWindowBuilder` and opening other hosts in the system browser via the opener plugin. This is a Rust change: compile and test on all three OSes.
